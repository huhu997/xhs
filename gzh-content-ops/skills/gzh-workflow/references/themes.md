## 二、版式库（8 种）

| 代号 | 版式 | 特征 | 适用 |
|------|------|------|------|
| L1 | 单栏通读 | 标准长文，舒适行距，最稳 | 所有通用 |
| L2 | 双栏杂志 | 图文左右交错，杂志感强 | 有配图的深度文 |
| L3 | 卡片流 | 信息卡堆叠，重点块化 | 清单 / 干货 / 多要点 |
| L4 | 时间轴 | 竖向节点串联 | 复盘 / 历程 / 事件线 |
| L5 | 大字报 | 金句超大字 + 短段 | 强观点 / 情绪文 |
| L6 | 留白禅意 | 超大间距，呼吸感 | 随笔 / 哲理 |
| L7 | 对话气泡 | Q&A / 访谈体 | 问答 / 访谈 / 观点碰撞 |
| L8 | 数据看板 | 数字块 + 图表 | 数据密集文 |

## 三、选型规则（题材 → 推荐主题 × 版式）

- 复盘 / 踩坑 → 实战墨绿 × L1/L4
- 日常记录 → 票据风 × L1
- 清单干货 → 卡片信息卡 × L3
- 带数据 → 数据看板 × L8
- 强观点短文 → 极客黑 × L5
- 科技 AI 话题 → 科技蓝 / 赛博银 × L1/L2
- 长文深度 → 橄榄手记 / 复古报纸 × L1/L6
- 政策 / 宏观 / 行业（金融号高频）→ 财经严肃 × L1/L8
- 国货 / 节令 → 国潮 × L2
- 温柔观点 / 生活 → 莫兰迪 × L6
- 哲理 / 慢思考 → 禅意留白 × L6
- 争议 / 情绪 → 大字报 × L5
- 年轻向夜读 → 暗夜霓虹 × L2
- 干净教程 → 极简白 × L1/L3

## 四、通用组件规范
- 正文中文优先 `Noto Sans SC` / `Microsoft YaHei`，标题用 `Noto Serif SC` 衬线加粗
- 主题 × 版式自由组合，但一套稿子只锁定 1 主题 + 1 版式，封面 / 插图 / 正文三处必须同源同款
- **主色 / 强调色的使用边界（配置级铁律）**：主色只用于**封面、刊头、章节标题、边线**；强调色只做**边框 / 细条 / 装饰**。
  **正文数据组件（数据卡、条形图、图例）不得用主题主色做底色，也不得用强调色写小字。**
  这条曾是「内容里的图看不清」的根源：旧版组件规范让主色兼任数据卡底色，出财经严肃稿必然做成深蓝底 `#0E2A47` + 金色 `#C8A24B` 小字，手机低亮度下发闷发虚，微信编辑器/深色模式一动背景就变白底白字。正文图块一律改用下节统一色板。

## 五、正文数据组件色板（跨主题统一，不随主色变）
S3 出任何承载数字 / 板块名的图块，一律用下表固定色值，**不许从主题主色或强调色里取**。理由：深色底 + 浅色字在手机上发虚且抗背景变动能力为零；中明度红绿压米灰槽辨识度低。

| 组件 | 固定色值 | 约束 |
|---|---|---|
| 数据卡底 / 分隔线 | `#FFFFFF` / `#D8DEE7` | 浅底深字，永不翻车 |
| 卡内主数字 / 标签 | `#1F2933` / `#44515F` | 标签 ≥14px，对比 ≥4.5:1 |
| 涨（数字文字） | `#C62828` | 红涨，白底 5.6:1 |
| 跌（数字文字） | `#0E7A45` | 绿跌，白底 5.4:1 |
| 涨条 / 跌条 | `#E03127` / `#159A5B` | 高饱和，条高 ≥14px |
| 条形槽底 | `#EDE9E0` | 浅槽，与条拉开明度 |
| 正文小字 | `#44515F`，≥14px | 禁用 `#8a93a0` / `#5b6b7a` 等浅灰 |

**微信兼容写法**：图块只用内联 `style=""`；两端对齐用 `<table>`（禁 `display:flex`）；禁 `border-radius`；写 `background-color` 而非 `background` 简写。
**交付校验**：`gzh.py render --width 375` 逐段审图块 → 定量算前景/背景对比度 → 推草稿后从 `draft/batchget` 回拉服务端 HTML 核对新色值真的进箱（别只改本地文件）。
完整铁律见 `team/roles/visual.md`「正文图块配色铁律」，踩坑记录见 `assets/tools/README.md` 坑 11。
