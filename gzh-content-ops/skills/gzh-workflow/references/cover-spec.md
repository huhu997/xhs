# 封面与插图规范

两条出图路线，默认走 A：

| 路线 | 何时用 | 中文 | 成本 |
|---|---|---|---|
| **A. Gemini 生图**（默认） | 写实场景、氛围图、需要视觉冲击 | 短标签清晰，长句会糊 | 零积分（吃 VIP 额度），见 `gemini-image.md` |
| **B. 本地 HTML/CSS 渲染** | 中文标题必须精确、纯排版型卡片、生图不可用时 | 绝对清晰 | 零成本，需 Chrome headless 截图 |

两条路线都必须遵守下方的尺寸与配色规则：**封面 / 插图 / 正文三处同源同款**。

## 一、尺寸（@2x 出图，按需缩放）

| 用途 | 比例 | 出图尺寸 | 备注 |
|---|---|---|---|
| **主封面（首选）** | **2.35:1** | 1880×800 | 一张覆盖订阅号列表 + 朋友圈 1:1 裁切 |
| 方封面（需要独立首图时） | 1:1 | 800×800 @2x=1600 | 进草稿箱首图 |
| 正文插图（横） | 16:9 | 1600×900 | 数据对比 / 机制拆解 / 展望 |
| 正文插图（竖） | 3:4 | 750×1000 @2x=1500 | 移动端长阅读 |
| 长封面（备用） | 21:9 | 1600×686 | 需要超宽横幅时 |

## 二、2.35:1 双比例安全区（关键）

微信会同时展示 **2.35:1**（订阅号列表）和 **1:1**（朋友圈分享）。

- 以 2.35:1 为画布，**所有关键内容（标题文字、核心主体）集中在中间 42% 宽度**的安全区内
- 安全区左右两侧只放背景装饰元素，不放文字和重要主体
- 按 2.35:1 构图 → 微信自动裁到 1:1 时，中间内容不被切割

> 这一条能替掉「21:9 + 1:1 + 3:4 各出一张」的三图方案：**一次出图，两处可用**。

## 三、渲染方式（路线 B）

- 用 HTML 文件 + Chrome headless `--screenshot` 导出 PNG
- CSS 内嵌，字体指定 `Noto Sans SC` / `Noto Serif SC`，避免系统字体缺字
- 配色取自 `themes.md` 的对应主题主色 + 底纸色，禁止临时换色

## 四、文案规则

- 主封面：一行主题 + 一行副文案，留白充足，不堆字
- 方封面：标题 + 一个视觉符号
- 插图：图文对应，一张图讲一个分句
- **图内数字克制**：扩散模型渲染数字易错。需要精确数字时用路线 B，或把数字留在正文表格、图只做场景

## 五、配色方向

- **A 股内容：红涨绿跌**；**美股内容：绿涨红跌**（写进 prompt，别指望模型自己懂）
- 角色/身份配色不得挪用涨跌色

## 六、质检

- 中文清晰、无乱码、无溢出
- 配色与所选排版主题一致
- 同一篇的所有图同属一套视觉语言
- AI 生图须标注「AI 生成」，并过 S5 合规

## 七、账号署名（图上的字跟着账号名走）

**署名属于配置，不属于某张图。** 唯一真源是 `config/account.md`，禁止在 `output/*/cover.html`、模板或脚本里手写账号名、也不许照抄上一篇的封面。

- 封面底部署名 / 刊头 / 图片落款一律写 `cover_byline`（当前为「薄肌小王 · 个人观察」）；账号全名 `account_name`（「薄肌小王翻盘实录」）只用于核对后台，不进封面。
- `old_names` 里的旧名（「中登小王」等）在任何**新图**上出现即不合格。
- 出图前：`python gzh.py account`（不确定加 `--live` 跟微信后台对昵称）→ 写署名 → `python gzh.py brand <本轮目录>` 扫旧名 → 再渲染。
- 封面必须由 `cover.html` 渲染出 PNG。`brand` 扫的是源码，PNG 里的字扫不出来；直接拿旧 PNG 改图会绕过闸门。
- 账号改名后按 `config/account.md` 第 4 节 SOP：改配置 → 扫全包 → 重渲染全部含署名图（重出 900 宽压缩版 + 1:1 分享卡）→ 重推草稿（`publish` 自动清同标题旧稿）→ 从微信服务端回拉封面确认。
