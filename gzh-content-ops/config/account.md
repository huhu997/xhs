## 2. 为什么单独拎出来

2026-11-09 用户指出「账号已经换名了，图片上相关的字也要跟着改」。根因不是某张图改错，而是**署名写死在 `cover.html` 里**，账号改名后没有任何机制通知出图环节，S3 照抄旧模板就会把旧名继续印到封面上，一路进草稿箱。

所以账号名属于**配置**，不属于某次产出。工具侧已加两道闸：
- `gzh.py account --live`：实时拉微信后台昵称，与 `account_name` 不一致就告警；
- `gzh.py brand <路径...>` + `publish` 内置检查：扫描 `.html/.md/.txt` 里的 `old_names`，命中即阻断推送（`--allow-old-brand` 才放行）。
- 注意：`brand` 扫的是**源码**（`cover.html`），不是 PNG。所以封面必须从 HTML 渲染，禁止直接改图 / 用旧 PNG 冒充。

## 3. 出图前必做（S3 视觉官）

1. 跑 `python gzh.py account` 看当前署名，不确定就加 `--live` 跟后台对一次。
2. 写 `cover.html` 时署名写 `cover_byline`，不要自己编。
3. 渲染完跑 `python gzh.py brand <本轮目录>`，有旧名先改再推。
4. 检查范围：封面底部署名、刊头、章节装饰文字、正文落款、视频号封面大字、分镜字幕里的自称。

## 4. 改名 SOP（以后再换名照做）

1. 改本文件的 `account_name` / `pen_name` / `cover_byline`，把旧名追加进 `old_names`（**不要删旧名**，历史图还要靠它扫出来）。
2. 全包扫一遍：`python gzh.py brand <专家包>/output --json`（不阻断，只列命中）。
3. 所有含旧名的 `cover.html` / 模板重渲染 → 重出 900 宽压缩版与 1:1 分享卡 → 按 375 真机宽看图。
4. 重推草稿：`gzh.py publish` 默认自动删同标题旧稿，别用 `--keep-old`；正文若也带署名，同步改 HTML。
5. 从微信服务端回拉封面（`material/get_material`）看一眼，确认发到草稿箱的是新图，不是本地自嗨。
6. 同步到运行缓存并按 `paths.md` 第七节校验。

- **栏目虚构角色名不算账号署名**：`assets/ip/长盈客栈*` 与 `skills/gzh-workflow/references/lanmu-wulinwaizhuan.md` 角色表里的「中登小王（掌柜）」有独立词源设定（中登=中国证券登记结算），是《A股每日复盘》群像的虚构角色，不随账号改名而改。全包跑 `brand` 时这些文件会命中，属预期，别机械替换——否则词源解释会一起错。
- 本文件自身、`assets/tools/README.md` 坑 12、`references/cover-spec.md` 第七节、`09-recap.md` 与各类合规/复盘报告里列举旧名是为说明规则，同样属预期命中。`brand` 默认跳过这些「记录/规范类」文档（文件名匹配），只对 `cover.html` / 排版 HTML / 模板等**出图源**做阻断；要审计全包可加 `--include-docs`。
- `_audit/`、`_drafts_raw.json` 等从服务端拉回的审查副本不是产出源，`brand` 已自动跳过 `_audit`。
- 其他账号（如「公众号AI实战手册」）不在本文件范围内，本专家包当前只服务上面这一个号。
