## ❌ 不可用（已实测排除，别重复试）

- **baoyu-infographic / baoyu-cover-image / baoyu-xhs-images（AI 生图类）** — 实测受阻（2026-11-05），**从待验降级为不可用**：
  - 三层坑叠加，非配置问题：
    ① **Bun fetch 代理 bug**：`bun` 下 `fetch` 走 HTTP_PROXY 会 `socket connection was closed unexpectedly`（同一代理用 curl / Python requests 完全正常）→ 必须改用 **Node 22 + tsx + 自写 fetch shim（https-proxy-agent）** 才能通。
    ② **代理间歇不稳**：`127.0.0.1:1080` 是**可用的 HTTP 代理**（非"死代理"），但对 `gemini.google.com` 时而 200 时而 000。
    ③ **Gemini 逆向 API 会话验证失败**：`--login` 能抓到完整 cookie（`__Secure-1PSID` 153 字符 / `__Secure-1PSIDTS` 85 字符，整套 __Host-GAPS/LSID 都在），但 `is_gemini_session_ready` 持续超时 → 疑似连续重试把代理 IP 打到 Google 限流。
  - **已沉淀可复用工具**：`engine/scripts/proxy-fetch.cjs`（Node 的 fetch 代理 shim：CONNECT 隧道、本机地址强制直连、`maxHeaderSize` 512KB 解 Google 大 header、跟 3xx 重定向、支持 signal）。原件在 baoyu 技能 scripts 下，包内为副本，可直接复用。
  - 复用入口：`node -r <包内 proxy-fetch.cjs> <tsx cli.mjs> main.ts ...`；env 需 `GEMINI_WEB_PROXY` + `HTTPS_PROXY`（Node shim 下本机直连已内置，Bun 时代才需额外 `NO_PROXY`）。
  - ⚠️ Windows 坑：脚本 `findExistingChromeDebugPort` 在 `win32` 直接 return null → **每次 `--login` 都会新开一个 Chrome 窗口**，无法复用已开窗口（用户已明确要求"一个窗口就够"，后续若要再试需先补这个 patch）。
  - **再启条件（二选一）**：① 配官方 API key（Google AI Studio / 通义 / 即梦 均有免费额度）走 `baoyu-image-gen` —— 推荐，最稳；② 补 Windows 单窗口 patch + 等代理 IP 冷却后再试逆向通道。
  - 调性：AI 艺术图，不进 D1 基线 5 图，仅作偶尔的"数据英雄图"。
- **Auto-Redbook（红主题）** — 排除，垫底偏丑，拉低系列调性。
