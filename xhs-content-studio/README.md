# 小红书内容工作室 · xhs-content-studio

> 第一性原理重构版。本质 = 把「某类人的真需求」×「创作者的真实价值」×「能跑通的变现路径」匹配上，并用数据验证匹配成不成立。
> 不是写稿机器，是 **引擎**：可复用方法论（engine）+ 单一事实源（state）+ 每账号计划（accounts）三层物理分离，换方向不烂。

## 一、架构（三层物理分离）

```
xhs-content-studio/
├── agents/xhs-content-studio.md   # 引擎规则 + 7 个 Gate（含 G-F 跨篇去雷同、G-H 内容张力，不绑任何方向）
├── engine/                        # 可复用方法论（永远干净）
│   ├── 挖掘pipeline.md            # 通用挖掘 SOP + 工具链（带时间戳可重跑）
│   ├── 排版路由.md                # verified 优先，[待验] 须先实测
│   ├── 能力注册表.md              # verified vs candidate，只承诺 verified
│   └── scripts/                   # 已验证脚本（CDP 抓数 + Apple 风渲染）
├── state/                         # 单一事实源（每次会话先读）
│   ├── facts.md                   # 真实事实 + 明确没做过（G-A 输入）
│   ├── direction.md               # 当前方向 + 变现路径（钉死）
│   ├── demands/                   # 带时间戳需求报告
│   └── measurements/              # 发布后数据回填（G-D 闭环）
└── accounts/                      # 每账号一份已验证计划
    ├── 薄肌小王_旧人设_已废/        # 反面教材（非现行）
    └── 薄肌小王/                    # 活跃账号：选题库 + G-A模板 + 发布包_D1
```

**为什么这么分**：旧版把"会腐烂的账号状态"误当"可复用引擎"，一换方向整包烂。现在状态全部物理隔离在 `state/` + `accounts/`，引擎 `engine/` 与任何账号无关。

## 二、7 个不可跳过的 Gate

| Gate | 锁的约束 | 不过后果 |
|---|---|---|
| **G-A** 人设事实核查 | 经验陈述须映射到 `state/facts.md`；**且每篇至少用 1 处真实资产当具体细节** | 编经历翻车 / 或全删成公共常识 |
| **G-B** 需求带时间戳 | 挖掘必标日期、可重跑 | 旧数字当真理 |
| **G-C** 选题从变现派生 | 先钉变现路径；**禁止从高赞标题公式倒推；每 3 篇至少 1 篇接主变现** | 内容形态错乱 / 忙半天不沾钱 |
| **G-D** 发布必回填 | 发完填 `state/measurements/` | 开环漂移 |
| **G-E** 只调 verified | 只用已验证能力 | 调跑不通的 skill |
| **G-F** 跨篇去雷同 | 逐层比对上一篇，**最高优先级看叙事骨架是否同构** | 读者觉得「这篇我看过」 |
| **G-H** 内容张力（正向） | 出稿前过六问：独家句 / 开头画面 / 人话 / 可截图细节 / 钩子不换皮 / 正文不短于自检表 1/3 | 交一份安全但没人看的说明书 |

> ⚠️ G-A~G-F 全是**防错型**闸门，全过只说明「不出事」，不说明「有人看」。G-H 是唯一的正向质量闸，2026-11-05 补入（D2B 六闸全 ✅ 仍被判定糟糕）。

## 三、出一篇稿 · 标准操作流（会话第一动作 = 读 state/）

> 照这 7 步走，任何一篇都不会翻车。

1. **读状态**：`state/direction.md`（方向）+ `state/facts.md`（红线 + 真实资产）+ `state/measurements/` 最近回填（校准）。
2. **定选题**：从 `accounts/薄肌小王/选题库.md` 或 `state/demands/` 选选题，先回答「把谁往哪一步变现推进」（G-C）；**高赞标题公式只能当参考，不能当选题依据**。
3. **写稿 + 过 G-A / G-F**：打开上一篇发布清单，先比**叙事骨架**再比表层（G-F）；填 `accounts/薄肌小王/G-A核查模板.md`；写正文时把 `facts.md` §一 的真实资产落成具体动作或场景，不编体验。
4. **过 G-H**：折叠全部自检表，只读正文，逐条过六问。**必须在出图前做**。
5. **出图（G-E）**：用 `engine/排版路由.md` 的 verified 工具——Apple 风（`marketing-card-render`，A/B/C 三种 treatment）或 瑞士风（`guizang-card-render`），一篇只用一套；按 `engine/scripts/render_*.cjs` 模板批量渲。
6. **发布**：按 `state/measurements/` 推荐时段发（虚拟品吃晚间 20:00–22:00 主峰），发完立即置顶钩子评论。**交付时正文全文直接贴给用户**。
7. **回填（G-D）**：发后 2h / 3天 / 7天 回填 `state/measurements/YYYY-MM-DD_主题.md`，作为下篇选题校准输入。

## 四、当前状态速览

- **方向**：主变现 = 小红书虚拟品（短链）；入口 = 信息整理（引流）；背书 = 投研（长链，不荐股）。
- **活跃账号**：`accounts/薄肌小王/`（D1 首篇已发，十几个观看，主因新号权重、配图偏冷为次因）。
- **质量复议（2026-11-05）**：`发布包_D2B_共享档案/` 的 6 闸全过但内容被用户判「有点糟糕」，已**降级为反面教材**（不参与 G-F 的「上一篇」比对，不得当范文复用）。第 2 篇需按 G-H 重写。
- **已验证能力**：`engine/scripts/` 的 CDP 抓数脚本 + `marketing-card-render`（Apple 暖色）+ `guizang-card-render`（瑞士风）+ `proxy-fetch.cjs`（Node 代理 shim）。
- **不可用**：baoyu 三件套（AI 生图，需官方 key 才能再启）、Auto-Redbook。
- **已废**：`accounts/薄肌小王_旧人设_已废/`（仅反面教材，非现行）。

## 五、换方向时怎么办

只改 `state/direction.md` + 跑 `engine/挖掘pipeline.md` 重挖，把报告存 `state/demands/`。`engine/`、`agents/` 一字不改——这就是三层分离的价值。
